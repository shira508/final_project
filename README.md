## 1️⃣ `model_test.py` – מודל השלמת התמונה (Inpainting)

זהו הקובץ המלא והמרכזי ביותר בפרויקט מבחינת השלמת תמונה. הוא כולל את כל הצינור (pipeline): Dataset → מודל → Loss → אימון → בדיקה.

### מבנה הקובץ

**א. `ColorInpaintingDataset` (מחלקת Dataset)**
טוענת שלישיית תמונות עבור כל קובץ: התמונה השלמה (`clean`), התמונה הפגומה (`damaged`) והמסכה הבינארית (`mask`) מתוך שלוש תיקיות מקבילות (`dataset/clean`, `dataset/damaged`, `dataset/mask`). כל תמונה עוברת:
- שינוי גודל אחיד ל-256x256
- נרמול ל-[0,1]
- הפיכת המסכה לבינארית קשיחה (0/1) עם סף 0.5
- סידור מחדש של הצירים לפורמט (C,H,W) המתאים ל-PyTorch

**ב. `UNet4ChannelsInpainting` (הרשת עצמה)**
רשת מסוג **U-Net** קלאסית עם קידוד-פענוח (Encoder-Decoder) וקפיצות (Skip Connections):
- **קלט של 4 ערוצים** – 3 ערוצי RGB של התמונה הפגומה + ערוץ אחד של המסכה (שירשור `torch.cat` לפני הכניסה לרשת). זו הדרך של הרשת "לדעת" איפה החור נמצא.
- Encoder: 3 שכבות `conv_block` (Conv→BatchNorm→ReLU פעמיים) עם `MaxPool2d` בין כל שכבה (64→128→256 ערוצים).
- Bottleneck: שכבת `conv_block` נוספת ל-512 ערוצים.
- Decoder: `ConvTranspose2d` (Up-sampling) + חיבור (`concat`) עם הפלט המקביל מה-Encoder (Skip Connection) + `conv_block` נוסף, בחזרה עד 64 ערוצים.
- שכבת פלט: `Conv2d` בגודל 1x1 ל-3 ערוצים + `Sigmoid` שמחזיר את הפלט לטווח [0,1].

**ג. `VGGPerceptualLoss` (Perceptual Loss)**
משתמשת ב-4 השכבות הראשונות של **VGG16** מאומן מראש (ImageNet), ומקפיאה את המשקלים שלו (`requires_grad = False`). ה-Loss הוא ההפרש המוחלט (L1) בין ה-*features* שה-VGG מחלץ מהתמונה שהמודל הפיק לבין ה-*features* של התמונה המקורית – זה עוזר לתוצאה להיראות "טבעית" ולא רק מדויקת פיקסל-לפיקסל.

**ד. פונקציית האימון `run_training()`**
- Optimizer: Adam עם `lr=1e-4`.
- ה-Loss הכולל בכל batch מורכב מ-3 רכיבים:
  ```
  total_loss = loss_valid + 5.0 * loss_hole + 10.0 * loss_perceptual
  ```
  - `loss_valid` – ה-L1 loss על הפיקסלים שהיו תקינים מלכתחילה (מחוץ למסכה) — כדי לוודא שהרשת לא "משבשת" את מה שכבר תקין.
  - `loss_hole` – ה-L1 loss רק בתוך אזור החור, עם משקל **פי 5** — כדי שהרשת תשקיע יותר "תשומת לב" בהשלמה עצמה.
  - `loss_perceptual` – ה-VGG loss שחושב מעל לבד רק על אזור המסכה, עם משקל **פי 10** — כדי לעודד תוצאה ריאליסטית ולא מטושטשת.
- שימוש ב-`clip_grad_norm_` (הגבלת נורמת הגרדיאנט ל-1.0) כדי למנוע "התפוצצות" גרדיאנטים באימון.
- שמירת משקלי המודל (`state_dict`) לקובץ `.pth` בסוף כל אפוק.

**ה. פונקציית הבדיקה `run_test()`**
מריצה השלמה על תמונה בודדת:
1. קוראת את התמונה וממירה אותה לגווני אפור כדי לזהות את הקרע (פיקסלים לבנים מוחלטים, מעל 254).
2. **שלב טרום-עיבוד קלאסי**: לפני הכנסה למודל, מפעילה `cv2.inpaint` (אלגוריתם TELEA הקלאסי של OpenCV) כמילוי ראשוני גס של החור.
3. משרשרת את התמונה שעברה מילוי ראשוני + המסכה ל-4 ערוצים ומזינה למודל המאומן.
4. מציגה תוצאה משולשת (Input / Mask / Output) עם `matplotlib`.

> 💡 שילוב כזה — מילוי גס קלאסי (`cv2.inpaint`) ואז חידוד ע"י רשת נוירונים — הוא טכניקה נפוצה לשיפור יציבות האימון, כי הרשת לא צריכה "להמציא" תוכן חדש מאפס אלא רק לתקן ולחדד מילוי גס קיים.

## 2️⃣ `Lip coloring.py` – מודל צביעת השפתיים (Colorization)

קובץ עצמאי המדגים את שלב הצביעה על איבר השפתיים, ומורכב משתי פונקציות עיקריות:

**א. `get_accurate_lips_mask(image_path)` – יצירת מסכה בינארית של השפתיים**
- משתמש במודל **MediaPipe Face Mesh** (468 נקודות ציון על הפנים).
- מגדיר שני מערכי אינדקסים קבועים: `UPPER_LIP` ו-`LOWER_LIP` – הנקודות המדויקות שמתארות את קו השפה העליונה והתחתונה.
- מצייר פוליגון מלא (`cv2.fillPoly`) על גבי מסכה שחורה, פעם עבור כל שפה.
- מרכך את קצוות המסכה בעזרת `cv2.GaussianBlur` – כדי שהמעבר בין השפתיים לעור יהיה טבעי (ולא "חיתוך" חד).

**ב. `color_lips_fast(image_path, mask)` – צביעת השפתיים במרחב צבע Lab**
- ממיר את התמונה מ-BGR למרחב **Lab** (ערוץ L=בהירות, A=ציר ירוק-אדום, B=ציר כחול-צהוב).
- מחשב את ערוצי הצבע החדשים (A, B) לפי נוסחה תלוית-בהירות:
  ```python
  L_norm = L / 255.0
  A_channel = 145 + (185 - 145) * (1.0 - L_norm)
  B_channel = 125 + (145 - 125) * (1.0 - L_norm)
  ```
  כלומר: ככל שהפיקסל כהה יותר (L נמוך), הוא מקבל גוון אדמדם-חם יותר — מה שיוצר מראה טבעי יותר של שפתיים לעומת צביעה שטוחה באותו הגוון בכל מקום.
- ממיר את שכבת ה-Lab הצבועה בחזרה ל-BGR.
- מבצע **Blending** ליניארי בין התמונה המקורית לתמונה הצבועה, לפי משקל המסכה המטושטשת (ולא מסכה בינארית קשיחה) — כך שהמעברים בשולי השפתיים חלקים.
- בסוף הקובץ יש דוגמת הרצה שקוראת לתמונה ספציפית מהמחשב, שומרת את התוצאה, ומציגה אותה מוגדלת פי 3 בעזרת `cv2.imshow`.

> הערה: הגרסה המתועדת בספר הפרויקט מבוססת על אותו רעיון (MediaPipe + Lab), אך עם נוסחת צביעה מעט שונה (תוספת ישירה לערוצי A/B לפי בהירות, ולא אינטרפולציה בין שני קצוות צבע כמו כאן) ומורצת כ-endpoint ב-Flask (`/api/color-lips`) ולא כסקריפט מקומי.

# ודאי שקיימות התיקיות הבאות עם קבצים תואמי-שם:

## 🔍 סיכום מהיר

- **השלמת תמונה** מבוססת היום בפועל על **U-Net בעל 4 ערוצי קלט** (תמונה+מסכה) עם **Perceptual Loss מבוסס VGG16**, ולא על ה-GAN (AOTBlock + Discriminator) המתואר כארכיטקטורה חלופית בספר הפרויקט – שתי הגישות קיימות בריפו כשלבים שונים בתהליך הפיתוח.
- **צביעת התמונה** מבוססת על **MediaPipe Face Mesh** לזיהוי איברי הפנים (בפועל מומש עד כה בעיקר עבור השפתיים) וצביעה במרחב צבע **Lab**, המפריד בין בהירות לצבעוניות ומאפשר לשלב בצורה טבעית עם התמונה המקורית.
- שאר הקבצים בשורש הריפו הם בעיקר שלבי ניסוי, בדיקה ולמידה עצמית לאורך הפרויקט (חלקם מסומנים במפורש כלא רלוונטיים לגרסה הסופית).
